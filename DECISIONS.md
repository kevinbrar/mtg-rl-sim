# Decisions

Dated decisions by Kevin (K) or Devin (D) that shape the project. Newest first.

- 2026-11-12 (D): For a count-one tracked-zone choice followed by `ChangeZone { target: Any }`, forward the unchosen complement only to a direct zone-move sub-ability (`ChangeZone`, `ChangeZoneAll`, or `PutAtLibraryPosition`). Non-movement follow-ups bind to the selected object, and an empty optional selection forwards nothing. This separates "the other"/"the rest" zone moves from selected-object anaphora under CR 608.2c-d.
- 2026-11-12 (D): Singular “a/an … card exiled this way” now lowers to an up-to-one `ChooseFromZone` from the parent tracked exile set, followed by a single `ChangeZone`. The runner's optional-prompt path is removed in favor of the real choice prompt. The `ChangeZoneAll` misparse predates patch 0007; that patch only fixed X and exposed the issue, so this corrects the earlier attribution. Vren V2 is now the only known-diff entry. This supersedes the earlier `choose_cards` prompt-mapping and digest-gate status entries below.
- 2026-11-12 (D): `choose_cards` queues one labeled-card group per card-choice prompt in FIFO order. For Anzrag's Rampage, Phase consumes the group at the optional prompt: empty declines; nonempty accepts only if every label is currently a creature in exile exiled by the spell. Its card data then runs `ChangeZoneAll` over the tracked set without a post-check; XMage keeps its actual card-selection prompt. A4 uses the existing Soul-Guide Lantern sacrifice activation to count an artifact put into a graveyard earlier that turn.
- 2026-11-12 (D): Resolved: the digest-pinned known-differences gate now makes `xmage-diff` honor `oracle/known-diffs.toml`. Vren V2 and Anzrag A5 are committed scenarios and the two accepted `engine-bug` entries; both engines' normalized projections are pinned.
- 2026-11-12 (D): Model known-difference triage on `pytest.xfail(strict=True)`: only an exact suite/scenario entry with category `engine-bug` or `xmage-bug` and matching SHA-256 digests for both normalized engine projections waives a divergence. Matching scenarios with entries fail stale, unsupported entries never waive, duplicates and malformed entries fail closed, and digest drift reports both observed hashes. Digests use the comparator's unordered-zone normalization before canonical JSON serialization. Changed registry entries are base/head whole-table differences; every added, edited, or removed entry's card must be listed in `cards:`. The baseline coverage parser accepts legacy entries with only a string `card`.
- 2026-11-12 (D): Scripted X casts require an explicit non-negative `x` exactly when the spell's mana cost contains X; never default X to zero. `trigger_targets` queues one group per future trigger-target prompt in FIFO order and must be scripted before the trigger is put on the stack. Empty queues, illegal targets, and unconsumed groups fail closed. An X=0 Lost in the Maze trigger has no target prompt, so no target group is queued.
- 2026-11-12 (D): `end_turn` advances through turn-start steps to the next turn's precombat main when another scripted action follows, resolving intervening triggers. For a terminal `end_turn`, stop at the next turn's Upkeep, after untap and before draw. A probe with a tapped P1 Forest showed XMage's prior `UNTAP` stop occurs before permanents untap, while Phase exposes the state at Upkeep; XMage now schedules `UPKEEP` so both runners project the same point. Evidence: `runs/card-scenarios/terminal-untap-probe-final/compare.log`.
- 2026-11-12 (D): A 0025-reverted binary with the patched card-data file is not a valid sensitivity run: that file already serializes Lady Octopus's `NthDrawThisTurn` comparator as `LE`. Use the pinned 988bc34 baseline card-data for the revert comparison; it leaves the trigger `Unknown`, and L1–L3 diverge. Evidence: `runs/card-scenarios/lady-octopus-no-0025-20261112/revert-run/compare.log` and `revert-baseline-run/compare.log`.
- 2026-11-12 (D): XMage auto-orders a pending trigger group only when every trigger has the same non-null source ID and exact rule text; otherwise strict choose mode fails with the trigger list. Phase's `advance_until_stack_empty` drains every pending order prompt by identity index, without an identical-only guard. Lady Octopus's repeated triggers have the same source and rule text, so their order is unobservable.
- 2026-11-12 (D): Under Kevin's Standard-only scope, do not prioritize scenario suites for the non-Standard-legal patched cards Narset of the Ancient Way, Karoo, and Gaea's Liege. Keep their patches; add a scenario suite only if a future PR touches one of them.
- 2026-11-11 (D): Reverting Phase patch 0002 leaves the Restless Prairie scenarios matching (2/2) because 0002 changes only the coverage subtype lexicon, not runtime activation. The scenario validates runtime behavior; coverage is handled by 0002's own coverage test. Evidence: `runs/card-scenarios/restless-prairie-no-0002-20261111/compare.log`. Do not add an artificial scenario failure or duplicate coverage assertion.
- 2026-11-11 (D): Scripted battlefield activation selects by a normalized activated-ability cost prefix and requires exactly one matching non-mana ability, failing closed for zero, multiple, or missing descriptions. A prefix is a compact stable selector that distinguishes abilities on one source; exact-one prevents ambiguous selection. Use XMage's regular `activateAbility` helper, which fails loudly when no ability matches; exclude `manaActivate:` because its failure path can warn and silently no-op.
- 2026-11-11 (D): Serialize file-backed H2 schema initialization with an exclusive OS `FileLock` at `<db dir>/<dbname>.init.lock`. The seed-17 smoke failure was a concurrent `CREATE INDEX IF NOT EXISTS cardNumberAsInt_index` collision: two Bridge JVMs share `Mage.Client.Bridge/db/cards.h2` (`DatabaseUtils.java:38-44`, `CardRepository.java:73`), and the deck snapshot lazily initializes `CardRepository` (`BridgePublishedDecklist.java:31-34,46-49`); the failed process left `cardsDao` null (`CardRepository.java:75-78`). Lock `CardRepository`, `ExpansionRepository` (same `cards.h2`), and `AuthorizedUserRepository` (`authorized_user.h2`) initialization. Staggering or pre-warming is launcher-specific and cannot protect all local, test, and CI entry points; a path-derived cross-JVM lock applies at the database boundary. Mage-Bench separately returns `exit_code=0` after a failed pilot (`orchestrator.py:425-431`); the driver fails closed, so supervisor exit propagation is out of scope.
- 2026-11-11 (D): Compare battlefield (CR 403), exile (CR 406), and hand zone projections without order by sorting their elements by canonical JSON; preserve top-first library and graveyard ordering (CR 404.2). Separate exact card names in `cards:` lists with semicolons because names may contain commas and do not contain semicolons.
- 2026-11-11 (D): XMage scenario fixtures with `library_top` must call `skipInitShuffling()` before game execution. `CardTestPlayerAPIImpl.addCard(Zone.LIBRARY, ...)` puts each addition on top, so the scenario runner's reverse insertion is correct for a top-first fixture; the missing shuffle suppression was the order defect. Keep the Phase and XMage library order significant.
- 2026-11-11 (D): Scenario fixtures must make every scripted mana payment forced, so neither engine chooses between interchangeable lands. Use distinct basic-land colors when the spell costs permit it; S4 uses a Mountain for Shock and a Plains for Essence Burn's {1}{R} availability.
- 2026-11-11 (D): Vren V2 is a Phase engine bug, not runner staleness: forcing `mark_layers_full` and `flush_layers` immediately before projection leaves the Rat tokens 2/2. Vren is a Rat Rogue; under CR 613 the continuous effect applies +1/+1 for each other Rat, and CR 608.2h checks the state after resolution. Each of two tokens therefore sees Vren and the other Rat and should be 3/3. Parsed token data has only constant `+1/+1` modifiers; patch `0005` changes opponent-exile counting and does not touch P/T layer evaluation. Do not change engine code in this runner branch.
- 2026-11-11 (K): option B — validate patched cards with per-card differential scenarios in phase-rs and XMage (Forge where XMage lacks the card), instead of requiring seeded full-game runs. Full-game lockstep coverage is open-ended; per-card scenarios and later audits of agent games target the real risks.
- 2026-11-11 (K): H2 scenario specs reject pre-marked damage fixtures in both runners. Mage's test API cannot seed marked damage without applying a real damage event; revisit this fixture only if a card scenario needs it.
- 2026-11-11 (D): Handle affirmative mana-based `UnlessPayment` choices Phase-first and pass their generated mana plan to XMage `GAME_ASK`, using the same validation as `GAME_SELECT`. - 2026-11-11 (D): Map Phase `TriggerTargetSelection` through the same XMage `GAME_TARGET` and legal-target comparison as spell targeting when the trigger has one target slot. Preserve fail-closed behavior for `ChooseTarget {target: None}` and multi-slot trigger targeting; trigger targets are not cast continuations.
- 2026-11-11 (D): Normalize XMage ability text by mapping `{this}` to Phase's `~`. When the bridge truncates playable text with `...`, recover it only from the source card's `rules` line with a unique normalized prefix match; omit display-only reminder text consistently, and fail closed on missing state/rules or zero/multiple matches.
- 2026-11-11 (D): Differential runs opt XMage into stopping at all modeled priority steps, rather than relying on its UI defaults to auto-pass upkeep, draw, and other non-main steps. `BridgeClient` sets both active-turn and opponent-turn skip flags when `xmage.bridge.stopAtAllPrioritySteps=true`; default behavior remains unchanged. CR 117.3a gives the active player priority at the beginning of most steps and phases, except untap; players usually do not receive priority during cleanup (CR 514.3, with the exception in 514.3a).
- 2026-11-10 (D): For a Phase-first cast macro, send a non-empty mana plan as the bridge's comma-separated string with `auto_tap=false`, and require the bridge acknowledgement and exact size. For an empty plan, omit `mana_plan` and send `auto_tap=true` to clear stale bridge state. If XMage needs mana where Phase needed none, it may auto-tap; the discrepancy is detected only by the next tapped-state projection comparison, not as a `mana_plan` divergence. Detect plan cancellation from the incremental game log's `[System] Spell cancelled` message, not `choose_action` result fields.
- 2026-11-10 (D): Build a mana plan from `ManaAdded` events emitted during a Phase cast macro. Resolve each source through the existing battlefield bindings and duplicate matcher, then use the unique XMage `'{T}: Add {C}.'` rules-line index for that color (omit the index for a single-ability source). Unknown, ambiguous, non-battlefield, repeated, or unmatched sources fail closed. The macro's request and asynchronous cancellation checks follow the policy recorded above.
- 2026-11-10 (D): Exclude Phase's UI-only `CancelCast` candidate from both seeded differential-policy selectors. It is a UI back-out, not a game action, and mapping it to XMage would validate a UI rewind rather than rules behavior. If no candidates remain, fail with `UnmappedPromptError`; retain `_action_task`'s unsupported-action guard.
- 2026-11-10 (D): Normalize an XMage empty-blocker prompt only when the matching turn/active player has a recorded non-empty Phase attack and Phase observed no blocker decision. XMage's possibleBlockers list is not legality-filtered, so this can mask a Phase bug that wrongly finds no legal blockers; a follow-up should attempt the XMage declaration and observe acceptance or rejection.
- 2026-11-10 (D): Differential runs set Mage-Bench's per-player interaction limit to 100,000; deterministic oracle play must not be auto-passed by an LLM-pilot loop guard.
- 2026-11-10 (D): Phase `ScryChoice` `SelectCards.cards` is the keep-on-top set (engine_resolution_choices.rs:2296–2323; CR 701.22a); the driver maps its complement to XMage bottom selections and fails closed outside scry 1.
- 2026-11-10 (D): Battlefield object mappings are bijective between `(Phase ObjectId, incarnation)` and XMage short IDs. Phase reuses an ObjectId as storage identity across zone changes, so the incarnation counter must be serialized and checked when pruning/rebinding (CR 400.7). Unbound duplicates are matched only when their observable per-object signatures agree; exact state ties are rules-equivalent for this mapping. XMage damage/attachment serialization is bridge-only and uses the shared stable-short-ID locator. Residual risk: unobserved per-object effects, such as temporary effects not reflected in current power/toughness, can differ despite equal signatures; bindings preserve later identity and projected state comparison can catch downstream divergence.
